# Career Quest

**Язык:** [English (ENG)](README.md) | **Русский (RU)** | [Қазақша (KZ)](README.kz.md)

Навигатор развития сотрудников для трека Halyk Bank на HackAlem AI. Включает рекомендации с объяснениями, карьерные траектории, добровольные активности, обновление навыков, журнал развития, HR-аналитику и загрузку тестовых данных жюри.

## Запуск

Требуется Node.js 22 или новее. Устанавливать зависимости и собирать фронтенд не нужно.

```sh
npm start
```

Если в Windows PowerShell запрещено выполнение скриптов, используйте `npm.cmd start`. Откройте **http://127.0.0.1:3000**.

| Рабочее пространство | Логин | Пароль по умолчанию |
| --- | --- | --- |
| Сотрудник E0028 — Akmaral Ismailova в предоставленном датасете | `employee` | `grow-together` |
| HR-специалист | `hr` | `support-growth` |

Переменная `EMPLOYEE_ID` позволяет связать демонстрационную учётную запись сотрудника с другим профилем. Имена берутся из загруженных данных. При запуске сервера на сетевом интерфейсе, отличном от loopback, необходимо задать собственные пароли.

## Предоставленный датасет

Архив `career_quest_dataset.zip` распакован в **data/source/**, а данные загружены в **data/state.json**. Исходный архив не изменён. Резервная копия предыдущего состояния приложения находится в **data/backups/**. Исходные записи, рабочее состояние и резервные копии исключены из Git.

- 200 сотрудников, 8 ролей.
- 40 активностей, включая обязательные процессы.
- 60 навыков и 32 профиля требований к сочетаниям роли и грейда.
- 2 743 записи об участии.
- Дата среза: **2026-10-01**. Приложение использует её как текущую дату для расчётов.

При первом запуске без сохранённого состояния сервер загружает `data/source/`, если эта папка доступна. Иначе он создаёт исходный демонстрационный датасет. `DATASET_MODE=demo` явно выбирает генерацию демонстрационных данных при отсутствии состояния. Существующее состояние всегда имеет приоритет.

Чтобы полностью заменить датасет, остановите сервер, распакуйте четыре файла данных стартового набора в `data/source/` и выполните:

```sh
npm run import:dataset
npm start
```

Можно указать другую папку с распакованными файлами: `npm run import:dataset -- /path/to/dataset`. Команда сначала проверяет данные, затем сохраняет резервную копию существующего состояния и атомарно заменяет его. Не запускайте эту миграцию при работающем сервере; для обновления данных без остановки используйте экран импорта HR.

Экран HR принимает исходные `employees.json`, `events.json`, `skills.json` и `activity_history.csv` вместе, объединённый JSON, а также отдельные профили и историю. Сохраняются JSON-обёртки, метаданные, профили ролей и описания уровней владения навыками. Проверка не меняет данные; при применении импорта проверяется версия текущего состояния. Профили, активности и навыки объединяются по ID. Загруженная история заменяет записи только тех сотрудников, которые представлены в файле истории. Пустой файл истории не изменяет существующие записи.

Экспорт HR — это нормализованный снимок приложения с исходными полями и базовыми уровнями последней оценки. Его можно повторно импортировать без двойного начисления прироста навыков. Дополнительные профили и история жюри в исходном формате загружаются без преобразования схемы. Пример, совместимый с предоставленным каталогом: `fixtures/jury-profiles.json`.

## OpenAI и локальный ИИ

Сервер поддерживает OpenAI, локальный Ollama и явно обозначенный режим многофакторных правил. API-ключи читает только сервер; они не передаются браузеру и не включаются в исходный код.

Для локальной настройки нового ключа скопируйте `.env.example` в `.env`, заполните `OPENAI_API_KEY` и перезапустите сервер:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=your-new-key
OPENAI_MODEL=gpt-4.1-mini
```

Не добавляйте `.env` в Git и не отправляйте ключи в чат. Переменные окружения имеют приоритет над `.env`. Ключ, заданный только в окружении процесса сервера, действует для этого процесса; после его завершения ключ нужно настроить снова.

Режим OpenAI использует [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Модель по умолчанию — [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini), поддерживающая структурированный вывод. Модель можно изменить через `OPENAI_MODEL`. ИИ выбирает 1–3 активности из проверенного списка кандидатов. Приложение дополнительно проверяет возвращённые ID, их уникальность и длину объяснений. Текст модели отображается отдельно от фактов, рассчитанных приложением, и может содержать ошибки.

**Передача данных:** в режиме OpenAI на `api.openai.com` отправляются роль, грейд, стаж, карьерная цель, формат работы, текущие навыки, подходящие активности и факты, полученные из истории участия. Имена сотрудников, ID сотрудников и руководителей, а также исходные записи истории не отправляются. В запросах задано `store: false`; это не означает гарантированного отсутствия хранения данных. Используйте этот режим, только если правила хакатона допускают такую обработку. Для режима локальных правил API-ключ не нужен.

Для полностью локального вывода запустите Ollama с установленной локальной моделью и настройте:

```dotenv
AI_PROVIDER=ollama
OLLAMA_MODEL=your-installed-model
OLLAMA_URL=http://127.0.0.1:11434
```

Адреса Ollama ограничены loopback; перенаправления отклоняются. Используйте локальную модель, а не модель Ollama с облачной обработкой. Для работы только по правилам задайте `AI_PROVIDER=rules`. Если провайдер не указан явно, наличие ключа OpenAI выбирает OpenAI, иначе наличие модели Ollama выбирает Ollama, а при отсутствии обоих используются правила.

Тайм-аут запроса — восемь секунд. Если нет ключа или модели, возникла ошибка, исчерпана квота, ответ неполный или выбор модели не прошёл проверку, приложение явно сообщает о переходе к правилам. Успешные рекомендации кешируются на пять минут для каждого сотрудника и версии датасета; изменение данных сбрасывает кеш. Скорость модели и целевое время ответа до 10 секунд нужно проверять с выбранной моделью и сетью развёртывания.

## Правила обработки данных и рекомендаций

- **Учёт последней оценки.** Исходные `skills` сохраняются в `assessed_skills`. Завершённые активности со значением даты строго позже `last_review_date` и не позже даты среза применяются в хронологическом порядке с учётом прироста и ограничения каждой активности. Повторный импорт заново рассчитывает навыки от базовой оценки, исключая двойной учёт. Активности в день оценки считаются уже учтёнными. В источнике указаны даты занятий или записи, а не точные даты завершения, поэтому для расчёта используется доступное поле `date`. Если своевременность завершения неизвестна, приложение её не выдумывает.
- **Карьерные цели.** Явно заданные `career_goal.target_role/target_grade` имеют приоритет. Без цели используется следующий грейд текущей роли. Для Lead без цели следующий грейд не создаётся. Отсутствующий навык имеет уровень 0. Целевые требования, в том числе при смене роли, определяются полями `role_profiles.required_skills` и `critical_skills`.
- **Доступность активностей.** Обязательные активности исключены из рекомендаций и каталога добровольного развития. Текущие роль и грейд должны соответствовать аудитории активности, все предварительные требования должны быть выполнены. Для активности по расписанию нужна предстоящая сессия или существующая запись на участие. Цель сменить роль не отменяет ограничения аудитории.
- **Завершение.** Завершённую активность нельзя проходить повторно, кроме регулярного клуба публичных выступлений `EV_036`. Каждая сессия клуба требует отдельной записи и не может быть зачтена дважды. Активности со статусом «в процессе» из исходных данных отображаются в разделе My plan; добровольный выход из них сохраняется при последующих пересчётах.
- **Порядок рекомендаций.** Учитываются сокращение разрыва до цели, размер разрыва, критичность навыка, успешное участие и случаи ухода, неявки или отказа, успешность конкретного формата — онлайн, очно или самостоятельно — и трудозатраты. Завершённые неповторяемые активности исключаются. Модель выбирает из лучших доступных кандидатов и объясняет компромиссы. Для сотрудников на удалённой работе отмечается, если рекомендуемая активность проводится очно.

Детерминированная оценка: `12 * gap_closure + 4 * gap_weighted_closure + 3 * format_completion_rate + min(relevant_completions, 3) - 5 * relevant_skips - 0.4 * hours`. Здесь учитываются сокращение разрыва, его взвешенное сокращение, доля завершений в данном формате, релевантные завершения, пропуски и часы. Во взвешенном сокращении разрыва критические навыки получают двойной вес. Для нового формата начальная нейтральная доля завершений равна 0.5.

```text
new_level = max(current, min(5, activity.max_level, current + activity.gain))
readiness = round(100 * sum(min(current, target)) / sum(target))
```

Навыки без целевого требования не увеличивают знаменатель показателя готовности. Готовность служит ориентиром развития, а не решением о повышении. Разрывы по отдельным навыкам и критические требования остаются видимыми.

## Язык интерфейса

Выберите **EN / RU / KZ** на странице входа или в шапке приложения. Доступны английский, русский и казахский. Выбор сохраняется в этом браузере и применяется к навигации, формам, датам, HR-экранам, названиям и описаниям активностей из предоставленного каталога, навыкам и фактам в рекомендациях. При переключении введённые данные и выбранные файлы импорта сохраняются. Объяснения ИИ запрашиваются на выбранном языке; кеш рекомендаций разделён по языкам. Кнопка KZ внутри приложения использует стандартный код казахского языка `kk`.

Имена, ID, названия файлов, код и исходные записи датасета не меняются. Неизвестный текст из пользовательских импортов остаётся на исходном языке. Выбор языка не изменяет языковое предпочтение сотрудника в датасете. Технические подробности ошибок нестандартного ввода могут оставаться на английском. Переключатель в начале этого файла меняет язык документации.

В демонстрации сотрудник **сам отмечает завершение**, и уровни навыков обновляются сразу, даже для выбранной будущей сессии. Это не подтверждение фактического посещения. В рабочей системе завершение следует проверять через платформу обучения. Дата среза фиксирована для воспроизводимой оценки на хакатоне.

## HR, конфиденциальность и хранение

HR видит общие дефициты навыков и закрытые профили сотрудников в алфавитном порядке. Публичного рейтинга сотрудников нет. Сигналы поддержки означают повторные неявки или отказы за 90 дней либо отсутствие недавнего завершения относительно даты среза. Это не оценка эффективности сотрудников и не прогноз увольнения. В журнале сохраняются все статусы, включая «в процессе», «прервано» и «просрочено».

Разделение прав сотрудника и HR проверяется серверными маршрутами. Сотрудник не может запросить чужой профиль; импорт, экспорт и командная аналитика доступны только HR. Cookies имеют атрибуты HttpOnly и SameSite=Strict; сессии действуют восемь часов. Запросы на изменение данных с другого источника отклоняются, число попыток входа ограничивается. Перезапуск сервера завершает сессии. Состояние хранится в JSON с атомарной заменой файла в рамках одного серверного процесса.

| Переменная | Значение по умолчанию |
| --- | --- |
| `HOST`, `PORT` | `127.0.0.1`, `3000` |
| `STATE_FILE` | `data/state.json` |
| `DATASET_DIR` | `data/source` |
| `EMPLOYEE_ID` | `E0028` |
| `EMPLOYEE_PASSWORD`, `HR_PASSWORD` | Демонстрационные пароли из таблицы выше |
| `COOKIE_SECURE` | Установите `true` при работе через HTTPS |
| `AI_PROVIDER` | Автоматический выбор, описанный выше |
| `OPENAI_API_KEY` | Не задан |
| `OPENAI_MODEL` | `gpt-4.1-mini` |
| `OLLAMA_MODEL` | Не задана |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |

Это прототип для хакатона с двумя демонстрационными учётными записями. Для промышленного использования нужны SSO, надёжная база данных, журнал аудита, шифрование хранимых данных, HTTPS и подтверждение завершения через платформу обучения. Не загружайте реальные персональные данные.

## Проверки

```sh
npm test
npm run check
```

Тесты проверяют права доступа, сохранение данных, сложные случаи ранжирования, исходные JSON-обёртки стартового набора, требования к ролям и критическим навыкам, цели смены роли, предварительные требования, активности по расписанию, обязательные и повторяющиеся активности, прирост навыков после оценки, идемпотентность импорта, CSV, валидацию запросов и ответов OpenAI, а также резервный режим при недоступности локальной модели. Проверка полного предоставленного датасета выполняется при наличии `data/source/`; независимые тестовые примеры проверяют его схему без этой папки. Автоматические тесты ИИ используют имитацию ответов и не расходуют API-кредиты.
