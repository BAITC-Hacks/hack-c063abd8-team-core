# Career Quest

**Тіл:** [English (EN)](README.md) | [Русский (RU)](README.ru.md) | **Қазақша (KZ)**

## Жоба туралы

Career Quest — HackAlem AI хакатонының Halyk Bank бағытына арналған қызметкерлердің кәсіби даму навигаторы. Ол қызметкердің қазіргі дағдыларын мақсатты рөл мен грейд талаптарымен салыстырып, келесі қадамдарды таңдауға көмектеседі. Қызметкер жеке даму жоспарын жүргізеді, ал HR маманы командадағы дағды жетіспеушілігін және қолдау қажет бағыттарды көреді.

## Іске асырылған мүмкіндіктер

- Қызметкер мен HR үшін бөлек кабинеттер; қазақша, орысша және ағылшынша интерфейс.
- Дағды деңгейлері, мақсатты рөлге дайындық және мансаптық даму жолы.
- Рөлді, грейдті, бастапқы талаптарды, кестені және қатысу тарихын ескеретін негізделген ұсыныстар.
- Іс-шаралар каталогы, қатысуға жазылу, жазылудан бас тарту, аяқталуды белгілеу және даму журналы.
- Каталог жеткіліксіз болғанда өздік практика тапсырмаларын автоматты түрде қосу және HR үшін қамту есебі.
- HR талдауы, қызметкерлерді іздеу және олардың профильдерін қарау.
- JSON/CSV импортын алдын ала тексеру, деректерді экспорттау, жеке жоспарлармен бірге толық сақтық көшірме жасау және қалпына келтіру.

## Шешім қалай жұмыс істейді

1. Сервер қызметкерлердің профильдерін, дағдыларды, іс-шараларды және қатысу тарихын жүктейді.
2. Қызметкер кіргенде оның дағдылары келесі грейдтің немесе таңдалған мансаптық мақсаттың талаптарымен салыстырылады.
3. Ережелер қолжетімді іс-шараларды бағалайды. Каталогта қажетті қадамдар болмаса, жүйе деңгей талаптары бар өздік практика тапсырмаларын қосады.
4. Қызметкер ең көбі үш ұсыныс пен олардың негіздемесін көреді. ЖИ қосылса, ол алдын ала тексерілген нұсқалардың ішінен таңдап, түсіндірме береді; жауап жарамсыз болса, ережелерге негізделген ұсыныстар көрсетіледі.
5. Қызметкер іс-шараға жазылып, демода аяқталғанын белгілейді. Жүйе дағды өсімін белгіленген шекке дейін есептеп, жоспарды, журналды және ұсыныстарды жаңартады. Бір аяқталудың қайталанған жазбалары қосымша өсім бермейді.

## Технологиялар

| Бөлік | Қолданылған технология |
| --- | --- |
| Сервер | JavaScript ES modules, Node.js 22+, кіріктірілген HTTP және файлдық жүйе модульдері |
| Интерфейс | HTML, CSS, фреймворксыз JavaScript |
| Деректер | JSON күй файлы, JSON/CSV импорты |
| Ұсыныстар | Жергілікті ережелер; қосымша OpenAI Responses API немесе жергілікті Ollama |
| OpenAI моделі | Әдепкі `gpt-4.1-mini`; `OPENAI_MODEL` арқылы өзгертіледі |
| Тексеру | Node.js кіріктірілген `node:test`, синтаксисті `node --check` арқылы тексеру |

`package.json` файлында сыртқы npm тәуелділіктері жоқ. Негізгі сценарийге API кілті немесе сыртқы сервис қажет емес.

## Архитектура

Браузердегі интерфейс → Node.js HTTP API → даму логикасы мен ұсыныстар → JSON күйі. ЖИ қосылғанда сұрауды сыртқы API-ге немесе жергілікті Ollama-ға сервер жібереді.

| Файл немесе қалта | Міндеті |
| --- | --- |
| `public/` | Интерфейс, аудармалар, навигация және ортақ компоненттер |
| `server.js` | Кіру, қолжетімділік құқықтары, API, импортты тексеру және күйді сақтау |
| `lib/domain.js` | Даму талаптары, қолжетімділік, ұсыныстар, прогресс және HR есебі |
| `lib/dataset.js`, `lib/dataset-loader.js` | Бастапқы деректерді оқу, тексеру және түрлендіру |
| `lib/catalog-repair.js` | Каталогтың жеткіліктілігін тексеру және практика тапсырмаларын қосу |
| `lib/ai.js` | OpenAI/Ollama сұраулары, жауаптарды тексеру және резервтік ережелер режимі |
| `data/source/`, `lib/seed.js` | Берілген деректер жинағы және демонстрациялық жинақ |
| `data/state.json` | Ағымдағы күй; іске қосылғанда жасалады немесе оқылады |
| `fixtures/`, `test/` | Қазыларға арналған импорт үлгісі және автоматтандырылған тесттер |

## Орнату және іске қосу

1. Node.js 22 немесе одан жаңа нұсқасын және репозиторийді көшіру үшін Git орнатыңыз. Node.js нұсқасын тексеріңіз: `node --version`.
2. Репозиторийді көшіріп, жоба қалтасына өтіңіз:

   ```sh
   git clone https://github.com/BAITC-Hacks/hack-c063abd8-team-core.git
   cd hack-c063abd8-team-core
   ```

3. Серверді іске қосыңыз. `npm install` және бөлек құрастыру қадамы қажет емес:

   ```sh
   npm start
   ```

Windows PowerShell ортасында `npm.cmd start` қолдануға болады. Браузерде **http://127.0.0.1:3000** мекенжайын ашыңыз. Серверді тоқтату үшін терминалда **Ctrl+C** басыңыз.

| Кабинет | Логин | Әдепкі құпиясөз |
| --- | --- | --- |
| Қызметкер (`E0028`) | `employee` | `grow-together` |
| HR | `hr` | `support-growth` |

Күй файлы бар болса, сервер соны оқиды. Файл болмаса, `data/source/` жинағын жүктейді; ол да болмаса, демонстрациялық деректер жасайды. `HOST`, `PORT`, `STATE_FILE`, `DATASET_DIR` және `EMPLOYEE_ID` орта айнымалыларымен тиісті баптауларды өзгертуге болады. Жергілікті компьютерден тыс желілік интерфейсте іске қосу үшін `EMPLOYEE_PASSWORD` және `HR_PASSWORD` мәндері қажет.

### ЖИ-ді қосу — міндетті емес

Егер `.env` файлы әлі болмаса, `.env.example` файлын жоба түбіріндегі `.env` файлына көшіріңіз. Бар баптауларды қайта жазбаңыз. Windows PowerShell пәрмені:

```powershell
Copy-Item .env.example .env
```

OpenAI қолдану үшін `.env` ішіндегі мәндерді толтырып, серверді қайта іске қосыңыз:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=your-key
OPENAI_MODEL=gpt-4.1-mini
```

Тек ережелерді қолдану үшін `AI_PROVIDER=rules` орнатыңыз. Жергілікті Ollama үшін алдымен оның сервері мен моделін дайындап, `AI_PROVIDER=ollama`, `OLLAMA_MODEL=your-installed-model` және `OLLAMA_URL=http://127.0.0.1:11434` мәндерін беріңіз. Репозиторийде Ollama моделі бірге таратылмайды.

`.env` Git жүйесіне қосылмайды және браузерге берілмейді. API кілтін тек сервер оқиды. Орта айнымалылары `.env` мәндерінен басым.

## Қазылар алқасы қалай тексере алады

1. Серверді іске қосып, `employee` есептік жазбасымен кіріңіз. **KZ** тілін таңдаңыз.
2. **Шолу** және **Даму жолым** бөлімдерінде ағымдағы деңгейлерді, мақсатты талаптарды және ұсыныстардың негіздемесін салыстырыңыз.
3. Қолжетімді іс-шараға жазылып, оның аяқталғанын белгілеңіз. Журналдағы жазбаны және көрсетілген өсімге сәйкес дағды өзгерісін тексеріңіз. Бұл әрекет жергілікті күйді өзгертеді.
4. Шығып, `hr` есептік жазбасымен кіріңіз. Команда есебін, каталогтың қамтылуын және қызметкер профилін қараңыз.
5. **Деректерді басқару** бөлімінде `fixtures/jury-profiles.json` файлын таңдаңыз. **Файлдарды тексеру** батырмасын басып, нәтижені қарап, тексерілген деректерді импорттаңыз. Бұл үлгіде үш қосымша қызметкер профилі бар; бастапқы 200 профиль бар күйде олардың саны 203 болады.
6. **Толық сақтық көшірмені жүктеп алу** арқылы жоспарларды қоса сақтаңыз. Қалпына келтіруді тексеру үшін файлды сол импорт экранында тексеріп, қалпына келтіруді қолданыңыз: ол ағымдағы күйді толық ауыстырады, содан кейін каталог қайта тексеріледі.

Автоматтандырылған тексерулер:

```sh
npm test
npm run check
```

Windows PowerShell ортасында `npm.cmd test` және `npm.cmd run check` қолданыңыз. ЖИ тесттері еліктелген жауаптармен жұмыс істейді және нақты API сұрауларын жібермейді.

[Бастапқы жинаққа арналған тест](test/catalog-repair.test.js) каталог толықтырылғаннан кейін дағды жетіспеушілігі бар, бірақ ұсынысы жоқ қызметкерлер санының **30-дан 0-ге** азаюын тексереді. Бағалаулар мен тарих өзгермейді. Бұл оқу тиімділігін емес, тест деректеріндегі каталогтың қамтуын көрсетеді; тест бастапқы жинақ бар кезде орындалады.

## Деректер және интеграциялар

- `data/source/` ішіндегі синтетикалық жинақ: 200 қызметкер, 8 рөл, 40 бастапқы іс-шара, 60 дағды, рөл мен грейдтің 32 талаптар профилі және қатысу тарихының 2 743 жазбасы. Жұмыс күйіндегі сандар импорт пен пайдаланушы әрекеттерінен кейін өзгеруі мүмкін.
- Негізгі файлдар: `employees.json`, `events.json`, `skills.json`, `activity_history.csv`. Деректердің кесінді күні — **2026-10-01**; есептеулер осы күнге сүйенеді. Форматтың сипаттамасы: [деректер жинағының README файлы](data/source/README.kz.md).
- HR импорты JSON/CSV файлдарын қабылдайды. Алдын ала тексеру файл мазмұнына, кіру сессиясына және деректер нұсқасына байланады. Деректер экспорты жеке жоспарларды қамтымайды; толық сақтық көшірме тіркелулер мен бас тартуларды да сақтайды. Кіру сессиялары мен API кілттері сақтық көшірмеге кірмейді.
- Сервер тоқтап тұрғанда бастапқы жинақпен күйді ауыстыруға болады: `npm run import:dataset`. Пәрмен бұрынғы күйдің көшірмесін сақтайды. Басқа қалта үшін: `npm run import:dataset -- /path/to/dataset`.
- OpenAI режимінде рөл, грейд, еңбек өтілі, мансаптық мақсат, жұмыс форматы, дағдылар және ұсынылатын іс-шаралардың негіздемелері API-ге жіберіледі. Есімдер, қызметкер мен басшы ID-лері және тарихтың бастапқы жазбалары жіберілмейді. Сұрауда `store: false` беріледі.
- Ollama байланысы жергілікті компьютер мекенжайларымен шектеледі. Ережелер мен каталогты толықтыру сыртқы API қолданбайды. Банк жүйелерімен немесе LMS-пен тікелей интеграция іске асырылмаған.

## Ағымдағы нұсқаның шектеулері

- Бұл — екі демонстрациялық есептік жазбасы бар хакатон прототипі. SSO, өндірістік дерекқор, толық аудит және оқу нәтижесін сырттан растау жоқ.
- Күй бір Node.js процесіндегі JSON файлында сақталады. Кіру сессиялары жедел жадта болады және сервер қайта іске қосылғанда аяқталады. Сервер HTTPS-ті өзі қамтамасыз етпейді.
- Аяқталуды пайдаланушы өзі белгілейді; демода болашақ сессияны да аяқтауға болады. Есептелген өсім нақты құзыреттіліктің расталған бағасы емес.
- Автоматты түрде қосылған іс-шаралар — ұсынылған өздік практика тапсырмалары. Олар ұйымдастырылған сыртқы курстарды, оқытушыны немесе нақты оқу материалдарының болуын білдірмейді; каталогты толықтыру дағдыларды өздігінен көтермейді.
- ЖИ түсіндірмелерінде қателер болуы мүмкін. ЖИ қолжетімсіз болса немесе жауабы тексеруден өтпесе, ережелер режимі қолданылады. HR қолдау белгілері жұмыс тиімділігінің бағасы немесе жұмыстан кету болжамы емес.
- Интерфейстегі импорт файлдарының жалпы көлемі 7 МБ-тан, серверге жіберілетін сұрау 8 МБ-тан аспауы керек. Жинақта кесінді күні берілсе, есептеулер сол күнге сүйенеді.
- Пайдаланушы импорттаған белгісіз мәтіндер бастапқы тілінде қалуы мүмкін.
